# Plan 010: Progressive story wiki

## Technical context
- **New file:** `lorekeeper/wiki.py`: stamps, story pages, names, folding, visibility, worked-out facts, chapter list, the index and card builders, and the fact edits. It imports `fm`, `store` and `timeinfo`; `ops.py` calls it.
- **Changed:** `ops.py` (four ops: `wiki`, `fact-add`, `fact-end`, `fact-remove`; `check` adds the stamp codes; an optional `guide` text per op), `store.py` (default `revealed_as` and `kind` roles, starter `sections` per type, starter sections on `create` in worlds without a story-wiki folder), `cli.py` (`--config`, `mcp --saga`, plain-text output for `wiki`), `mcp.py` (descriptions with the guide text, saga filter, instructions), `serve.py` (Story Wiki folder in the live-reload stamp), `__main__.py` (runs as `python <vendor>/lorekeeper`), `templates.py` (stamped facts, a rename, a reveal), the editor (Wiki tab), docs.
- **Stack:** stdlib only; vanilla JS module; CSP unchanged. Page text is rendered as DOM text nodes only.

## Design decisions
1. **Stamp grammar.** `\[\s*ch\s*(\d+)\s*(?:[-–]\s*(\d+)\s*)?\]` at the very end of a fact, any case. Any other `[ch…]`-looking marker (unreadable, or not at the end) is STAMP_UNREADABLE; an end below its start is STAMP_RANGE. In frontmatter, a stamp is read from a link value's suffix (`"[[X]] [ch 4]"`).
2. **Facts.** A body is split into sections at headings of level 2 or deeper (the `# Title` line is skipped). Inside a section a fact is one top-level list item plus its continuation and nested lines, or one paragraph; blank lines end paragraphs; HTML comments and fenced code are not facts. Each fact keeps its line span, so edits touch only its lines. Facts before the first `##` heading form an untitled section.
3. **Chapter values.** `first_appearance` and stamps read `CH003`, `ch 3` or `3`. A narrative item's number is its `order`, else its `chapter` field, else the first number in its id, else in its name. Narrative items never become entries.
4. **Story layer.** Built once per project on first use (`wiki.story(p)`, cached like `item_dates`):
   - with `story_wiki` set, companions are read from that folder (`fm.parse`; pages without `type` are ignored), attached to an item by their `page` link, else by name (stem minus ` (story)`), else standalone;
   - without it, each item's own page is its story page;
   - `## Names` entries that map to an item are added to `p.by_alias` with `setdefault`, after which link maps are rebuilt, so they never override a name, stem or alias.
5. **Visibility.** A fact is visible at N when `from ≤ N` and `to` is empty or `≥ N`; an unstamped fact takes its story page's appearance (none = always). An entry appears at its companion's `first_appearance`, else its item's. Complete mode is `N = None`: everything visible.
6. **Names.** The shown name at N is the latest-starting `## Names` entry covering N, else the item's name. Complete mode shows the item's name and lists all names with their ranges.
7. **Folding.** `revealed_as` (from the story page's fields, else the item's) gives a target and a reveal chapter (its stamp, else the page's appearance). At N ≥ reveal, or in complete mode, the entry folds into its target, following chains with a cycle guard. Folded facts merge under matching headings (case-insensitive), unmatched headings come after, each fact tagged `as` the folded entry's shown name.
8. **Spoiler guard.** In progressive cards, links to entries hidden at N become plain text, and a visible link whose target's shown name differs gets that name as its label (`[[Kresh|the hooded rider]]`). Frontmatter fields are left out.
9. **Complete cards in a story-wiki world** add `body` (the working page's body) above the companion sections, and `fields`.
10. **Worked-out facts** (person: Where, Knows, Relationships; group: Relationships), added to a section only when it has no visible written fact; a missing section is added after the written ones. Events count when visible at N; relationship links count when their stamp, else their page's appearance, is ≤ N and both ends are visible. Hidden `learns` targets are left out.
11. **Chapter list.** From the lowest used number (0 if a prologue is used, else 1) to the highest number used by any stamp, `first_appearance`, name or reveal. Labels come from narrative items with that number, real pages before in-memory cards, using a card's `title` when it has one.
12. **Fact edits.**
    - `fact-add`: one-line text, no stamp of its own, from ≥ 0, to ≥ from. Appends `- text [ch F]` or `[ch F-T]` after the section's last non-blank line, or adds `## Section` at the end. A missing companion is created at `<story_wiki>/<type plural>/<name> (story).md` with `type`, `page` and the type's starter sections; `--type` makes a standalone one with `canonical_name` and `first_appearance`.
    - `fact-end`: finds the first fact in the section whose text starts with the given text (case and spacing ignored), and writes its end; an unstamped fact gets its page's appearance (else 1) as start. `--reopen` clears the end.
    - `fact-remove`: deletes the fact's lines.
    - All three: the page's line endings are kept; a stale `version` is CONFLICT with the current version in `data`; writes use `atomic_write` with the read sha as `expect`; NOT_FOUND and INVALID messages name the fix.
13. **Ops and AI.** `Op` gains an optional `guide` (what it does, when to use it, what it returns, one example). MCP tool descriptions and CLI `--help` show summary plus guide. `wiki` is read-only; the three fact ops write.
14. **Settings elsewhere.** `--config FILE` on the CLI: the settings JSON is read from that file and `--root` is the project folder as given (it must exist). `mcp --saga` lists and runs only read ops plus the fact ops; anything else is FORBIDDEN with a message that Wiki pages change through the saga pipeline. `__main__.py` puts its parent folder on `sys.path` when run as a file.
15. **Live reload.** `serve.stamp` also scans the story-wiki folder.
16. **Editor Wiki tab.** Toolbar with the picker (`Complete`, `Chapter N — name`, remembered in `localStorage` inside try/catch) and a filter. Left: index groups with counts. Right: the card with its own toggle (previous, next, select), shown name, "Appears in chapter K", other names and "also", sections with facts, quiet chapter markers, ended facts marked in complete mode, "as …" and "worked out" tags. Each section has "Add a fact"; each written fact has "No longer true after chapter…". Local mode calls the fact ops and offers Undo (`fact-remove` or `fact-end --reopen`). Saga mode queues a `request` naming the entry, section, text and chapter. Index and card are refetched when the stamp or the chapter changes; the last result is drawn first, so live reload does not flicker. Below 900 px the index sits above the card.
17. **Sagas.** `_system/lorekeeper.json` gains `"story_wiki": "../Story Wiki"` (relative to the Wiki project). Companions use the saga's chapter stamps. The shared skill `story_wiki_update.md` holds the after-freeze routine; the one pointer goes where the pipeline describes `freeze`. `.mcp.json` runs `python ${CLAUDE_PROJECT_DIR:-.}/_system/vendor/lorekeeper --root .../Wiki --config .../_system/lorekeeper.json mcp --saga`.
